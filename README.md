# 뮤직마블 · Music Marble

음악사의 네 시대를 여행하며 명곡의 **가상 음악 이용권**을 뮤직코인으로 거래하는 수업용 온라인 보드게임 프로토타입입니다.

## 실행

Node.js 20 이상이 필요합니다. 외부 패키지 설치는 필요하지 않습니다.

```sh
npm start
```

[http://localhost:5173](http://localhost:5173)에서 열립니다. `npm run dev`도 같은 서버를 실행합니다. npm이 없는 환경에서는 `node server/server.js`로 직접 실행할 수 있습니다. 수정 후 브라우저를 새로고침하세요.

### 여러 기기에서 수업하기

1. 한 컴퓨터에서 서버를 실행합니다.
2. 참가자는 같은 네트워크에서 `http://서버컴퓨터의IP:5173`으로 접속합니다. 다른 기기에서 `localhost`를 입력하면 서버에 연결되지 않습니다.
3. 방장은 닉네임으로 **새 게임방**을 만듭니다.
4. 친구들에게 **사이트 주소 + 6자리 공유 코드**를 전달합니다.
5. 친구들은 각자 닉네임과 코드로 입장합니다. 한 방에는 **최소 2명, 최대 5명**이 참가합니다. 방 안에서 닉네임은 중복할 수 없습니다.
6. 방장이 4 / 8 / 12라운드와 시작 코인을 정하고 시작합니다. 1라운드는 첫 주자(방장)가 보드를 한 바퀴 완주하는 기준입니다. 첫 주자가 설정한 바퀴 수를 완주한 차례의 퀴즈·거래 등 활동을 마치면 게임이 종료됩니다. 다른 참가자의 완주나 모든 참가자의 한 차례 진행은 라운드를 올리지 않습니다. 이미 시작한 방은 신규 입장이 막힙니다.
7. 다른 코드를 사용하면 같은 서버에서 독립적인 다른 게임이 동시에 진행됩니다.

기본 서버는 `0.0.0.0:5173`에서 대기합니다. 기기 간 연결은 운영체제 방화벽과 학교 네트워크 정책의 허용이 필요합니다. `HOST`와 `PORT` 환경변수로 주소와 포트를 변경할 수 있습니다.

인터넷에서 서로 다른 네트워크로 접속하려면 **Node.js 서버를 실행하는 호스팅**과 HTTPS 주소가 필요합니다. GitHub Pages 같은 정적 호스팅만으로는 실시간 방 기능이 동작하지 않습니다. 이 저장소에는 배포를 위한 Dockerfile을 포함했으며, 현재 외부 서비스에는 배포하지 않았습니다.

```sh
docker build -t musicmarble .
docker run --rm -p 5173:5173 musicmarble
```

## 음악사 캐릭터 30종

새 방 만들기·코드 참가·봇과 혼자 플레이 모두 닉네임과 함께 캐릭터 30종 중 하나를 미리 보며 선택할 수 있습니다. 「랜덤으로 정하기」를 선택하면 서버가 배정합니다. 코드 참가 시 이미 사용 중인 캐릭터는 안내 후 다른 캐릭터를 선택해야 합니다. **같은 방에서는 사람과 봇을 포함해 모두 다른 캐릭터**를 사용하며, 서로 다른 방은 독립적으로 배정합니다.

대기실의 「다시 뽑기」는 다른 참가자의 캐릭터를 제외하고 새 캐릭터를 고릅니다. 혼자 플레이에서는 첫 주사위를 굴리기 전 배정 창에서 다시 뽑을 수 있습니다. 시작 후에는 캐릭터가 고정되며, 같은 브라우저에서 이어하기를 해도 유지됩니다. 보드 위 말·참가자 목록·결과 화면에 같은 캐릭터가 표시되고, 팀 색상의 받침으로 구분합니다. 첫 화면에서 전체 30종을 둘러볼 수 있습니다.

바흐, 헨델, 비발디, 하이든, 모차르트, 베토벤, 슈베르트, 쇼팽, 슈만, 멘델스존, 리스트, 클라라 슈만, 바그너, 베르디, 브람스, 차이콥스키, 드보르자크, 그리그, 생상스, 비제, 무소륵스키, 파니 멘델스존, 라흐마니노프, 릴리 불랑제, 드뷔시, 라벨, 사티, 스트라빈스키, 쇤베르크, 거슈윈을 게임용 3D 스타일로 재해석했습니다. 캐릭터 이미지는 3×2 구성의 투명 스프라이트 시트 5장으로 제공됩니다. 기존 캐릭터 없는 기록은 플레이어별 기본 캐릭터로 표시할 수 있습니다.

## 혼자 봇들과 플레이하기

첫 화면에서 **봇과 혼자 플레이하기**를 선택하세요. 닉네임, 봇 수(1–4명), 게임 길이(4 / 8 / 12라운드)를 정하면 기다림 없이 바로 시작합니다. 나와 봇을 합쳐 최대 5명이며, 모두 1,200 MC로 시작합니다.

봇은 매 게임 무작위 닉네임을 갖고, 같은 규칙에 따라 주사위·이용권 구입·공연 기획·퀴즈를 자동 진행합니다. 판단에는 무작위 선택이 포함됩니다. 퀴즈 정답 확률은 65%이며, 거래는 잔액과 제안 가격을 확인해 수락 또는 거절합니다. 플레이어 목록에서 `BOT` 표시로 구분합니다. 봇이 먼저 거래를 제안하는 기능은 아직 없습니다.

봇은 서버에서 차례별로 진행합니다. 방의 모든 화면 연결이 끊기면 멈추고, 첫 화면의 「이전 게임 이어하기」로 재접속하면 계속합니다. 내 차례를 자동으로 진행하지는 않습니다. 서버를 재시작하면 다른 게임과 마찬가지로 방이 초기화됩니다.

## 구현된 게임

- 비스듬히 내려다보는 입체 24칸 보드, 두께·타일 그림자·색상별 게임 말·공연 기획 표시
- 음악 정원 중앙 이미지와 입체 주사위, 필요할 때 「평면 보기」로 전환 가능
- 시계 방향 이동, 서버에서 생성하는 주사위, 시작점 통과 보상
- 바로크·고전주의·낭만주의·근현대 4시대, 작곡가 8명, 작품 16곡
- 가상 이용권 구입, 다른 플레이어에게 이용료 지급
- 같은 작곡가 2곡: 이용료 ×1.5 / 같은 시대 4곡: ×2 (시대 보너스 우선, 중복 없음)
- 작품당 100 MC로 1회 공연 기획: 기본 이용료 +20 MC 후 컬렉션 배율 적용
- 작품별 거래 제안 → 상대 참가자의 화면에서 수락 / 거절; 제안자는 취소 가능
- 은행 반납: 구입가와 공연 기획비의 50% 회수
- 음악사 사건 카드 24종, 음악사·저작권 퀴즈 28종과 해설
- 정답 보상 80 MC + 배움 1점; 한 차례당 선택 퀴즈 1회, 퀴즈 칸에서는 필수
- 파산·탈락 없이 잔액 한도 내 비용 지급, 부족액 면제
- 방장의 조기 종료, 동점 공동 순위, 결과·성찰 질문 텍스트 다운로드
- 모바일 / 태블릿 / 데스크톱 반응형 화면, 키보드 조작, 모달 포커스

총점 = 보유 코인 + 이용권 구입가 + 공연 기획비 + 배움 점수 ×50. 실제 예술적 가치나 학생의 음악적 능력을 평가하는 점수가 아닙니다.

## 실시간 구조

브라우저 → HTTP 명령 → 서버 규칙 검증 → 방별 상태 변경 → SSE로 같은 방의 참가자에게 갱신합니다. 별도 데이터베이스나 WebSocket 라이브러리 없이 Node.js 표준 모듈로 실행됩니다.

- 방마다 별도의 멤버·보드·코인·차례·퀴즈·사건 덱·거래·기록 보유
- 참가자별 무작위 토큰으로 자기 차례의 명령만 허용, 방장만 시작/종료
- 거래 수락은 수신자만 가능; 클라이언트가 보낸 주사위 값은 사용하지 않음
- 상태 버전 검사로 중복 클릭과 오래된 요청 거절
- 서버 스냅샷에 참가 토큰을 포함하지 않음
- 정적 파일은 `index.html`, `src/`만 제공; 서버 코드와 Git 파일 비공개
- 첫 접속·새로고침 시 시작 화면 표시, 「이 브라우저의 이전 게임 이어하기」를 선택하면 저장된 참가 정보로 복원. 게임 화면에서 일시적인 네트워크 단절은 자동 재연결

## 프로토타입 범위와 운영상의 제한

**게임 진행은 단일 서버 프로세스 메모리에 있습니다.** 서버를 재시작하면 모든 방이 초기화됩니다. 참가 토큰은 현재 브라우저의 localStorage에 저장됩니다. 다른 기기에서 닉네임과 코드만으로 기존 플레이어의 자리를 되찾을 수는 없습니다. 한 브라우저 프로필은 한 참가자 세션을 기억하므로, 동일 기기에서 여러 명을 시험하려면 서로 다른 브라우저/프로필을 사용하세요.

연결이 끊긴 플레이어의 자리는 유지되며, 그 플레이어 차례는 재접속할 때까지 기다립니다. 방장은 수업을 종료할 수 있습니다. 탈퇴·교체·자동 차례 넘김·교사 전체 방 관제는 아직 구현하지 않았습니다. 모든 연결이 종료되고 24시간 동안 변경이 없는 방은 정리합니다. 최대 500개 방, 방당 최대 30개의 SSE 연결, IP당 분당 1,200개의 변경 요청 제한이 있습니다.

여러 서버 프로세스나 자동 확장으로 운영하려면 공유 저장소와 방별 이벤트 전달 계층이 필요합니다. 프록시를 사용하면 SSE 응답 버퍼링을 끄고 장기 연결을 허용해야 합니다. HTTP 테스트는 로컬에서 **20개 방 / 100개 SSE 연결**을 검증하며 실제 인터넷 환경의 용량 보장을 의미하지 않습니다.

가상 이용권은 실제 작품·음원 저작권이나 이용허락을 부여하지 않습니다. 외부 녹음 음원은 포함하지 않았습니다. 가격과 사건의 코인 효과는 게임용 설정입니다. 시대 구분은 근사치이며 베토벤 등 여러 시대에 걸치는 작곡가도 있습니다.

저작권 학습 참고: [문화체육관광부 — 저작권법상 권리자](https://www.mcst.go.kr/site/s_policy/copyright/netizen/netizen03.jsp), [한국저작권위원회 — 공유마당 만료저작물 안내](https://gongu.copyright.or.kr/gongu/main/contents.do?menuNo=200091). 작품과 녹음·연주에 관한 권리를 구별하는 기본 개념을 다루며, 구체적인 이용 조건은 실제 사용 방식에 따라 확인해야 합니다.

화면 글꼴은 Google Fonts를 사용하며 네트워크가 없으면 시스템 글꼴로 표시합니다. 게임 실행 자체에는 외부 API가 필요하지 않습니다.

## 검증 / 빌드

```sh
npm test
npm run build
node server/server.js --dist
```

`build`는 정적 화면 파일을 `dist/`에 복사합니다. **빌드 후에도 실시간 플레이에는 서버가 필요합니다.** `/api/health`로 서버 상태를 확인할 수 있습니다.

이 개발 환경에는 npm 실행 파일이 없어 동일한 스크립트를 `node --test`, `node scripts/build.mjs`로 직접 실행해 통과했습니다.

테스트는 게임 규칙, 5인 완주, 거래 수락 권한, 방 분리, 5명 정원, 중복 요청, 새로고침 세션 복원, SSE 갱신, HTTP 경로 제한, 20개 방/100개 연결을 검증합니다.

### 퀴즈 수정 내역

기존 Q5(가상 이용권)·Q8(게임 가격)을 삭제하고, 바로크·고전·낭만주의·음악 저작권 각 5문항씩 20문항을 추가했습니다. 나머지 기존 8문항은 유지해 총 28문항입니다. 기존 문항 ID는 유지하며 신규 문항은 Q11–Q30입니다. 질문·선택지·정답·해설과 저작권 참고 자료는 `src/data.js`에서 관리합니다. 서버도 이 데이터를 읽으므로 수정 후 재시작해야 하며, 새 게임에서 적용됩니다.

### 음악사 사건 카드 운영

수익·기회 8장, 손실·위험 8장, 음악사·산업 변화 8장으로 총 24장입니다. 새 방마다 24장을 섞어 뽑으며, 한 묶음 안에서는 중복 없이 순서대로 사용합니다. 카드 문장과 코인 변화는 게임용 가상 시나리오이며, 작품 보유 여부와 관계없이 카드를 뽑은 참가자에게 적용됩니다. 손실 목록에서 부호가 생략된 저작권 침해(150)·공연 취소(100)·계약 위반(100)은 음수로 적용합니다.

카드를 뽑으면 금액이 한 번만 자동 정산됩니다. 카드 다시 보기는 추가 정산하지 않습니다. 잔액이 부족하면 기존 수업 규칙에 따라 가진 코인까지만 지급하며 파산·탈락은 없습니다. 보호기간 만료 카드는 가상 수익 100 MC 차감만 적용하며 작품 이용권을 삭제하거나 별도로 이용료를 변경하지 않습니다.
